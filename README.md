# Standalone MRTCore

This repository contains a copy of [MRT Core](https://github.com/microsoft/ProjectReunion/tree/main/dev/MRTCore), packaged so it can be used separately from WinUI 3. It also includes a set of MSBuild targets that create a self-contained PRI file from the contents of a given folder, for use with MRT Core.

## Using This Library

After you add this package to your project, you need to specify a `MRTCoreResourceRoot`. This is a directory, normally next to your project file, that contains the resources you want compiled into a PRI file. Strings should be placed in a `*.resjson` file. This file contains a simple dictionary where the keys are the identifiers used to look up the strings and the values are the strings. To localize strings, vary images by DPI, and so on, use the same filename conventions as are used with WinUI 3 and the standalone MSIX build tools (described in the Microsoft documentation).

To customize the generation of the PRI file, you can set the `$(MRTCoreConfigurationFile)` MSBuild property. If you don't set this, a default PRI configuration will be used. The PRI configuration included with this package embeds all files by default (which is very difficult to do with the MSIX or WinUI 3 tooling). Additionally, dots in identifier keys will not be modified by the PRI compiler, which is different than the behavior of the MSIX or WinUI 3 tooling.

This library will generate a PRI file named after your MSBuild `$(TargetName)`. If such a PRI file is being generated elsewhere in your build (perhaps because you are using WinUI 3 or are building an MSIX), the contents of the PRI file generated by this library will be merged into the pre-existing PRI file automatically. Note that if the PRI file is being merged this way, the rule concerning dots in identifier keys will not be propagated to the rest of the file, preserving the semantics required by WinUI 3 and MSIX.

**Important:** Since this library uses CSWinRT and CppWinRT, some configuration of your project is required for it to work properly:

* You must be building with a _single_ runtime identifier. If you build with multiple runtime identifiers, the DLLs will be copied into a subdirectory of the build output, where Windows cannot find it.
* You must add the below XML snippet into your app's SxS manifest (`app.manifest` file).

If you do not do either of these things, the WinRT APIs in Microsoft.ApplicationModel.Resources.dll will not be found at runtime. While the library might still appear to work (if you have the Windows App SDK MSIX packages installed, its copy of these APIs may be used instead), this is not portable and should not be relied upon.

```xml
<dependency>
  <dependentAssembly>
    <assemblyIdentity name="Microsoft.ApplicationModel.Resources" version="1.0.0.0" />
  </dependentAssembly>
</dependency>
```
